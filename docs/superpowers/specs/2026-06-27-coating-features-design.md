# Блок «Особенности коллекции» на странице товара

Дата: 2026-06-27

## Контекст

На странице товара (`/models/[slug]`) сейчас нет места, где объясняются преимущества конкретного типа покрытия (ПЭТ / Эмаль / Эмалекс) — только сухие технические характеристики в `product-specs`. Пользователь хочет блок по образцу `sofiadveri.ru` («Особенности коллекции Элегант»): слева список пунктов-преимуществ, справа — пара фото и подпись выбранного пункта, с лёгким редактированием контента в будущем.

## 2. Компонент

**Файл:** `src/components/catalog/CoatingFeatures.vue` (новый, Vue-остров)

Структурно копирует уже работающий паттерн `ProductColorPicker.vue`: `ref` на активный индекс, `computed` на активный пункт, переключение по клику (работает одинаково на клике и тапе — без хover-зависимого поведения, бессмысленного на тач-устройствах).

```ts
const props = defineProps<{ features: CoatingFeature[] }>()
const activeIdx = ref(0)
const active = computed(() => props.features[activeIdx.value])
```

Разметка: `<ul>` слева с кнопками-пунктами (номер-кружок + заголовок; у активного пункта дополнительно показывается `description`), `<div>` справа — две фотографии в ряд (`grid-template-columns: 1fr 1fr`) + подпись с заголовком активного пункта под фотографиями. Если `images[i]` пустая строка — рендерится та же серая SVG-плейсхолдер-иконка, что и в `ProductColorPicker.vue`, а не битый `<img>`.

Кружок-номер активного пункта — акцентный teal (`var(--color-accent)` / `#14b8a6`), а не красный как в референсе sofiadveri.ru — сохраняем фирменный цвет ВФД, как и во всех остальных переделках интерфейса в этом сезоне работ.

## 3. Адаптивность и размещение

- Десктоп: `display: grid; grid-template-columns: 360px 1fr` (список / фото), аналогично текущему `.product-layout`.
- Мобильные (`max-width: 900px`, тот же брейкпоинт, что уже используется в `.product-layout`): одна колонка — список сверху, фото на всю ширину под ним.
- `client:visible` для гидратации — секция не входит в критический путь первого экрана (CLAUDE.md: ниже-сгиба контент гидратируется через `client:visible`/`client:idle`).

**Файл:** `src/pages/models/[id].astro` — импорт `coatingFeatures` и `CoatingFeatures.vue`, рендер между текущим закрывающим `</div>` блока `.product-layout` и секцией `accessories-section`:

```astro
{coatingFeatures[coatingSlug as CoatingSlug]?.length > 0 && (
  <section class="coating-features-section">
    <div class="container">
      <h2 class="coating-features-section__title">Особенности коллекции {seriesName || coatingName}</h2>
      <CoatingFeatures client:visible features={coatingFeatures[coatingSlug as CoatingSlug]} />
    </div>
  </section>
)}
```

## Границы изменений

- Контент (тексты, фото) заполняется/правится пользователем напрямую в `coating-features.ts` после реализации — структура и 3 пункта-заготовки на каждое покрытие даются как стартовый набор, не финальный текст.
- Не трогаем Supabase, `getStaticPaths`, существующие компоненты `ProductColorPicker.vue`/`series-descriptions.ts` — только новый файл данных, новый компонент и точка интеграции в `models/[id].astro`.
- Без серверной валидации/проверки на «ровно 2 фото» — TypeScript-тип `[string, string]` гарантирует это на этапе редактирования данных.
